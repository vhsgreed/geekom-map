# cartofile 0.1: design spec

Status: NOT BUILT. Superseded 2026-11-08 by the prior-art probe in section 11. Working name `cartofile` (see Decisions).
Source: generalises `~/projects/geekom-map` (live since 2026-11-03, 77 units, ~$0.45 total model spend).

## 1. Purpose

Map a person's machine into an Obsidian vault without them having to set it up.
Each project, repo and folder becomes a note that says what it is, its exact name and
path, its size and when it was last touched. Area pages and a Home page link the notes.
Model-written summaries are an extra the user turns on.

**Who it's for:** anyone with more projects in `~/` than they can remember, who wants a
browsable map of what they have and what each thing is called. It works with any agent
or none. Obsidian is the viewer, but the output is plain markdown.

**What it is not:** a search engine, chat with your files, a file organiser or a
backup tool. It never moves, edits or deletes anything outside its own vault.

## 2. Viability criteria (numbers, dated)

- **Release gate (v0.1):** on a fresh Ubuntu VM, `pipx install cartofile && cartofile run ~/fixture`
  builds a vault in under 10 minutes. It makes zero network calls and writes nothing
  outside the vault directory. The test suite checks the network and write claims.
- **Pull gate (decides v0.2), 60 days after release:** at least 15 GitHub stars or 3 issues
  from people other than the author. Below that, archive it, and Karl's own copy keeps working.

## 4. Pipeline

```
cartofile init   -> cartofile.toml (detected units, written for the user to edit)
cartofile scan   -> .cartofile/inventory.json   (read-only walk, no network)
cartofile build  -> vault/                       (no network, atomic swap)
cartofile digest -> .cartofile/digests.json     (opt-in, the only networked step)
cartofile run    =  scan + build (+ digest if enabled in config)
```

### 4.1 Detection (scan)

- **A unit** is a git repo, or a directory holding a project marker: `pyproject.toml`,
  `package.json`, `Cargo.toml`, `go.mod`, `*.godot`, `*.sln`, `CMakeLists.txt`, `SKILL.md`,
  `Makefile`. Detection stops descending once a unit is found.
- **Roots:** `~` by default, at depth 3, or the paths given in config.
- **Noise list, never units:** caches, toolchains, browser profiles, package stores (`.cache`,
  `.local/share/Steam`, `node_modules`, `.venv`, `snap`, `.var`, `~/.mozilla`, `~/.config/google-chrome`, ...).
- **Loose folders** (no marker, but with files the user made, such as `~/Documents/x`) become
  one note with a file table. This is the geekom-map "loose-file folder" rule.
- **Grouping** (geekom-map's FAMILIES): optional in config. `[[group]] name=, paths=[...]` collapses
  several units into one note with a table.
- **Areas** (geekom-map's tree): optional in config as `area = "..."` per unit or by glob. Without
  config, the area is the unit's top-level directory (`src`, `projects`, `Documents`).
- **Per unit:** size, file count, newest and oldest mtime, git (first commit, last commit,
  remote, branch, dirty), README name, privacy tier.

### 4.2 Vault (build)

- **Layout:** `Home.md`, `areas/<area>.md`, `units/<unit>.md`, `archive/` (dormant after 30 days,
  configurable), `_meta/` (inventory, log).
- **Unit note:** frontmatter (area, status, created, last_touched, size, path, privacy), then
  **Call it** (exact name + path, copy-paste ready), What it is, State, Contents table,
  Related, `## My notes`.
- **Ownership:** every `## My notes` section survives rebuilds, as does any file outside
  `Home.md`/`areas/`/`units/`/`archive/`/`_meta/`. Builds go to a temp dir and swap at the end,
  so a failure leaves the old vault intact. These are geekom-map behaviours, carried over with tests.
- **Links (deterministic only):** a unit's text mentioning another unit's path or distinctive
  name makes a Related link, with the reason shown (geekom-map `links.py`).
- **Without digest**, "What it is" falls back to the first paragraph of the README, then to "(no summary)".

### 4.3 Digest (opt-in)

- **Off by default.** Turn it on with `[digest] enabled = true` or `cartofile digest`.
- **Endpoint:** any OpenAI-compatible endpoint, via `base_url`, `model` and an API key from an env
  var named in config. The README leads with a local Ollama example, then OpenRouter.
- **`--dry-run`** (and always on first use) lists each unit, the files that would be sent, the
  characters and estimated tokens, and the cost estimate. The real run needs `--yes` or an interactive yes.
- **Spend cap:** `max_usd` per run (default $1), measured from reported usage and stopped at the cap.
  Only changed units are re-digested (content hash).
- **Never sent:** deny-listed paths (`.ssh`, `.gnupg`, `.password-store`, keyrings, `.secrets`,
  `*.pem`, `*.key`, `.env*`, browser profiles), files over 300 KB, binaries. Secret-shaped strings
  are redacted before sending (geekom-map's `SECRET` regex plus generic high-entropy tokens).
  Units marked `privacy = "private"` in config are header only.
- **Output:** JSON `what / why / state / value_now`. The model's opinion is labelled as such in the note.

## 5. Interfaces

- **Config:** `cartofile.toml` in the vault's parent or `~/.config/cartofile/`. `init` writes
  a commented file listing every detected unit.
- **CLI:** `init`, `scan`, `build`, `digest [--dry-run] [--yes]`, `run`, `--vault PATH`,
  `--config PATH`, `-v`. Exit codes: 0 ok, 1 step failed (vault untouched), 2 usage.
- **Scheduling:** documented only (a cron line and a systemd user timer in the README).
  No installer.

## 6. Tech

Python >= 3.11 (for `tomllib`), stdlib only (urllib for HTTP). Published on PyPI and run
with `pipx`. Linux is tested. macOS should work but is not CI-tested. Windows is out of scope.

## 7. Testing

- A fixture home tree under `tests/fixture/` holding git repos, marker dirs, noise, a fake `.ssh`
  and a file with a planted fake key.
- **Tests:**
  - detection
  - noise and deny-list
  - the scan and build steps open no sockets (a socket guard fails the test if one does)
  - no writes outside the vault (snapshot diff of the fixture)
  - My-notes survival
  - atomic swap on an injected failure
  - idempotent rebuild
  - digest against a local fake OpenAI server: payload excludes deny-listed paths, redaction applied, cap enforced
- CI on GitHub Actions (Ubuntu).

## 8. Left out of 0.1 (YAGNI / parked)

- Model-judged links and the gold test (geekom-map `model_links.py`, `gold_test.py`). They need a labelled set per user.
- Journal filing (`journal.py`), the review queue and the glossary.
- STATUS.md and ledger integration. A generic "ledger file" hook could come in v0.2.
- Hermes skill catalogue units. Plain `SKILL.md` detection covers the basic case.
- Multi-machine / SSH roots, watch mode, an Obsidian plugin, embeddings, chat, a GUI.
- Demo GIF and launch post. Parked until the release gate passes (spec-scope rule).
- Migrating Karl's own vault. It keeps running on geekom-map. Switching is a separate decision after v0.1.

## 9. Bet terms (proposed)

Stake: about 6 h agent time, under 1 h of Karl's (this review, one test run), and at most $2 in
model spend (digest tests use a fake server). Deadline: **2026-12-06**. Kill: the release gate
isn't passed by the deadline. On kill, the repo stays private and nothing is published.

## 10. Decisions taken without explicit sign-off

1. **Name `cartofile`:** PyPI free, 0 GitHub repo collisions, github.com/cartofile free.
   Alternatives checked and free: `lay-of-the-land` (CLI alias `lotl`), `whatsonmybox`, `mapmymachine`.
2. **License GPL-3.0:** it's an end-user tool (the GPL column from 2026-11-08). MIT if you prefer adoption.
3. **Python 3.11 minimum, stdlib only.**
4. **Digest off by default and local-first in docs:** Ollama first, OpenRouter second.
5. **Everything in section 8 left out.**
6. **Viability numbers in section 2** (15 stars / 3 external issues in 60 days).
7. **Bet terms in section 9.**

## 11. Prior art (probe 2026-11-08, added after the draft)

| Tool | Created | Stars | Overlap |
|---|---|---|---|
| oscarmiranda90/motherbrain (JS, MIT) | 2026-09 | 0 | Closest. Marker-based disk scan, one markdown note per project with YAML frontmatter, user prose never overwritten, zero dependencies, an agent SKILL.md for summaries, static wiki publishing. Not Obsidian-specific, code projects only. |
| justi/armillary (Python, MIT) | 2026-04 | 2 | Scans project folders, ACTIVE/STALLED/DORMANT status, MCP server, Streamlit dashboard. No vault. |
| liujs123456/revive (TS, MIT) | 2026-05 | 3 | Scans local folders + GitHub, Claude rates each project's health. No vault. |
| nosarthur/gita | 2018 | ~2k | Multi-repo git status only. |
| Obsidian FolderBridge, RepoAgent, gitsummarize | various | | Neighbours: mounting folders, per-repo docs. |

What only cartofile would do: Obsidian-native output (area hubs, wikilinks, a Home tree), non-code units
(loose folders, documents, study material) and a tested no-network / no-write guarantee for the
digest step. The AI summary step is not novel. The three closest tools got 0-3 stars in 2-7 months,
so the 15-star pull gate in section 2 is below base-rate odds.
